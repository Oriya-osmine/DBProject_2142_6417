# שלב ה' - פיתוח ממשק משתמש גרפי (GUI) ב-Python

## 📌 מבוא לשלב ה'

בשלב זה פיתחנו אפליקציית שולחן עבודה מודרנית (Desktop Application) המשמשת כממשק ניהול מלא (Front-end) עבור בסיס הנתונים של המטבח. האפליקציה מתממשקת ישירות ל-PostgreSQL, מאפשרת ניהול נתונים נוח וידידותי למשתמש (CRUD), ומשלבת בתוכה את כל הלוגיקה העסקית שפיתחנו בשלבים הקודמים (שאילתות, צפיות, פונקציות ופרוצדורות).

## 🛠️ טכנולוגיות בהן השתמשנו

- **שפת פיתוח:** Python 3
- **ספריית ממשק משתמש (GUI):** `customtkinter` (לעיצוב מודרני בסגנון Dark Mode) ו-`tkinter.ttk` (עבור טבלאות נתונים - Treeview).
- **ספריית התממשקות ל-DB:** `psycopg2` (מנהל ההתקשרות מול PostgreSQL).

---

## 📁 ארכיטקטורת המערכת (מבנה הקבצים)

כדי לשמור על קוד נקי, מודולרי ותקני (ומניעת שגיאות של Circular Imports), הפרויקט חולק ל-6 קבצים נפרדים הנמצאים באותה תיקייה:

1. **`shared.py`** - קובץ תשתיות. מכיל את הגדרות החיבור לבסיס הנתונים (DB_CONFIG), פונקציות עזר, ואת המחלקה הגנרית `GenericDataTable` שאחראית על תצוגת הטבלאות בכל מסכי האפליקציה.
2. **`main.py`** - הקובץ הראשי המריץ את האפליקציה. מכיל את תפריט הניווט הצדדי (Sidebar) ואת הלוגיקה למעבר בין המסכים השונים.
3. **`tab_settings.py`** - מסך הגדרות. מאפשר למשתמש לעדכן את פרטי ההתחברות ל-DB (שם מסד, משתמש, סיסמה ו-Host) ולבדוק את תקינות החיבור (Test Connection) ישירות מתוך האפליקציה.
4. **`tab_crud.py`** - מסך ניהול הנתונים הראשי. מכיל תתי-לשוניות עבור 7 הטבלאות המרכזיות במערכת.
5. **`tab_queries.py`** - מסך להפעלת שאילתות מורכבות (משלב ב').
6. **`tab_advanced.py`** - מסך "פעולות מתקדמות" להפעלת Views, פונקציות (כולל Refcursor) ופרוצדורות (משלבים ג' ו-ד').

## ✅ מענה לדרישות הפרויקט

### 1. ביצוע 4 פעולות CRUD על טבלאות המסד

מסך ה-CRUD מאפשר שליפה (Read), הוספה (Insert), עדכון (Update) ומחיקה (Delete) עבור כל הטבלאות הבאות:
`Chefs`, `Kitchen Stations`, `Kitchen Orders`, `Menu Items`, `Preparation Tasks`, `Hygiene Inspections`, `Food Prep Logs`.

- **עדכון מבוסס מפתח (Update):** המשתמש מזין את מזהה הרשומה (ID), לוחץ על "Load Data", והמערכת שולפת את כל הנתונים וממלאת את השדות אוטומטית לקראת העדכון.
- **מחיקה בטוחה:** כל לחיצה על כפתור Delete מקפיצה חלון אישור (Confirmation Dialog) למניעת מחיקה בטעות.

### 2. תצוגת מפתחות זרים (Foreign Keys) בצורה ידידותית

**לפי הדרישה:** חל איסור על המשתמש לראות או להזין מספרי ID עבור מפתחות זרים.
**הפתרון שלנו:** \* בתצוגת הטבלאות השתמשנו בשאילתות `JOIN` כדי להציג את שמות הערכים (למשל, הצגת "Grill Station" במקום "Station ID: 1").

- בטופסי ההזנה והעדכון, יצרנו פונקציית עזר `fetch_fk_mapping` שמייצרת **רשימות נפתחות (ComboBox)** עם שמות בלבד. המשתמש בוחר את השם הרצוי, ופייתון מתרגמת אותו מאחורי הקלעים ל-ID המתאים לפני שליחת שאילתת ה-SQL.

### 3. הפעלת שאילתות, פונקציות ופרוצדורות

- **שאילתות (שלב ב'):** מסך `Queries` מכיל כפתורים המריצים שאילתות מורכבות (כמו עומס לפי תחנות) ומציגים את התוצאות בטבלה.
- **פונקציות (שלב ד'):** * פונקציית *חישוב עומס לשף\* מחזירה ערך סקלרי שמוצג למשתמש בחלון קופץ.
  - פונקציית _תפריט התחנה_ שמחזירה **Refcursor**, מטופלת בפייתון על ידי משיכת שם הסמן (Cursor Name) וביצוע `FETCH ALL FROM` בתוך טרנזקציה (Transaction) - כדי להזרים נתונים בצורה בטוחה ומהירה לטבלה.
- **פרוצדורות (שלב ד'):** הממשק מספק שדות להזנת פרמטרים ומריץ את הפקודה `CALL` במסד הנתונים (למשל, העברת משימות בין שפים).

### 4. סינון ומיון מתקדם (Filter & Sort)

הוספנו יכולת מקצועית למסכי ה-CRUD: רכיב `FilterSortPanel` הניתן לפתיחה וסגירה.
המשתמש יכול לבחור עמודה, להקליד טקסט חופשי, והמערכת מבצעת סינון חכם (באמצעות `ILIKE` ב-SQL לחיפוש גמיש) ומיון (ASC / DESC) כדי להקל על מציאת נתונים בטבלאות גדולות.

### 5. וולידציה ושמירה על יציבות (Guards & Validations)

- **בדיקת התחברות (Connection Guard):** האפליקציה בודקת שהיא מחוברת ל-DB לפני שהיא מנסה לשלוף נתונים. אם החיבור נופל, היא מנתבת את המשתמש למסך ההגדרות.
- **בדיקת קיום נתונים (Pre-Validation):** לפני הפעלת פרוצדורות (כמו העברת משימות בין שף ישן לחדש), פייתון מוודאת מול ה-DB שה-ID של השפים שהוזנו אכן קיים (`check_exists`), ומציגה שגיאה מובנת למשתמש במקום שהמסד יקרוס.
